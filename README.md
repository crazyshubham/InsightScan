# Article NLP Pipeline

Scrapes articles from a list of URLs, then runs sentiment analysis and readability metrics on each article. Results are written to a single Excel file. The pipeline is split into three stages: scraping, analysis, and output generation.

---

## Folder Structure

```
project/
│
├── articles/                        # Auto-created. Contains one .txt file per scraped article
│
├── StopWords_Auditor.txt            # Stopword lists used during NLP cleaning
├── StopWords_Currencies.txt
├── StopWords_DatesandNumbers.txt
├── StopWords_Generic.txt
├── StopWords_GenericLong.txt
├── StopWords_Geographic.txt
├── StopWords_Names.txt
│
├── positive-words.txt               # Master dictionary: positive words
├── negative-words.txt               # Master dictionary: negative words
│
├── Input.xlsx                       # Input file with URL_ID and URL columns
├── Output_Data_Structure.xlsx       # Reference file showing expected output column order
│
├── scraper.py                       # Stage 1: Fetches and saves article text from URLs
├── sentiment.py                     # Module: Sentiment scoring (imported by main.py)
├── readability.py                   # Module: Readability and text metrics (imported by main.py)
├── main.py                          # Stage 2: Runs NLP pipeline and writes Output.xlsx
│
├── Output.xlsx                      # Final output (generated after running main.py)
├── failed_urls.txt                  # Log of URLs that could not be scraped (generated by scraper.py)
│
├── requirements.txt
└── README.md
```

## Setup

**1. Create and activate a virtual environment**

```bash
# Windows
python -m venv venv
venv\Scripts\activate

# macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

**2. Install dependencies**

```bash
pip install -r requirements.txt
```

**3. Download NLTK data**

```bash
python -c "import nltk; nltk.download('punkt'); nltk.download('punkt_tab'); nltk.download('stopwords')"
```

---

## Running the Pipeline

**Step 1 — Scrape articles**

```bash
python scraper.py
```

Reads `Input.xlsx`, visits each URL, and saves the article text as a `.txt` file inside the `articles/` folder. The folder is created automatically if it does not exist. Adds a 1-second delay between requests. Any URL that fails is logged to `failed_urls.txt`.

**Step 2 — Run NLP analysis and generate output**

```bash
python main.py
```

Reads `Input.xlsx` and the scraped `.txt` files from `articles/`, runs sentiment and readability analysis on each, and writes the results to `Output.xlsx`.

---

## Output Columns

| Column | Description |
|---|---|
| `URL_ID` | Unique identifier for each article, taken from the input file |
| `URL` | Source URL of the article |
| `POSITIVE SCORE` | Count of positive words found in the cleaned text |
| `NEGATIVE SCORE` | Count of negative words found in the cleaned text (reported as a positive number) |
| `POLARITY SCORE` | Overall sentiment direction: `(Positive − Negative) / (Positive + Negative + 0.000001)`. Range: −1 to +1 |
| `SUBJECTIVITY SCORE` | Proportion of opinion-bearing words: `(Positive + Negative) / (Total cleaned words + 0.000001)`. Range: 0 to +1 |
| `AVG SENTENCE LENGTH` | Total word count divided by total sentence count |
| `PERCENTAGE OF COMPLEX WORDS` | Proportion of words with more than 2 syllables |
| `FOG INDEX` | Gunning Fog readability score: `0.4 × (Avg Sentence Length + Percentage of Complex Words)` |
| `AVG NUMBER OF WORDS PER SENTENCE` | Same as avg sentence length |
| `COMPLEX WORD COUNT` | Number of words containing more than 2 syllables |
| `WORD COUNT` | Total words after removing stopwords and punctuation |
| `SYLLABLE PER WORD` | Average syllable count per word across all words in the article |
| `PERSONAL PRONOUNS` | Count of `I`, `we`, `my`, `ours`, `us` (case-insensitive). The country abbreviation `US` is excluded. |
| `AVG WORD LENGTH` | Sum of character lengths of all words divided by total word count |

## Notes

**`failed_urls.txt`**
Created by `scraper.py`. Each line contains a `URL_ID` and its URL separated by a tab, representing a request that failed (e.g. due to a network error, timeout, or non-200 response). Re-run `scraper.py` after fixing connectivity issues to retry these URLs — successfully scraped files will not be overwritten since the script skips nothing, but already-existing `.txt` files in `articles/` will simply be re-saved.

**Missing articles in `articles/`**
If `main.py` cannot find the `.txt` file for a given `URL_ID`, it fills all 13 metric columns with `0` and moves on. Check `failed_urls.txt` to see which URLs were not scraped and re-run `scraper.py` to attempt them again before re-running `main.py`.
